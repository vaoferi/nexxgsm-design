# SPEC.md — поточний стан проєкту NexxGSM Design

Оновлено: 2026-09-08. Формат — за розділом 5 AGENTS.md.

---

**Ціль:** публічний лендінг «Dell BIOS Unlock Tool» (NexxGSM Service Point S.R.L.), який конвертує відвідувача в покупку коду ($28.20) або звернення через Telegram-бот; далі — мовні/культурні копії з канонічної версії.

**Контекст:** одна канонічна версія `versions/en-US-landing/` (стратегія «довести до результату → розмножити»). Продакшн: Docker-контейнер `nexxgsm-landing` на Synology NAS, bind-mount папки з цього репозиторію, публікація **http://nlmhelp.keenetic.link:18080/** через порт-форвардинг зовнішнього Keenetic. Деталі інфраструктури — `README.md` (розділ «Production») та `docs/architecture-decisions.md`. Правила роботи агента — `AGENTS.md`.

**Поточний стан (що вже працює):**
- канонічний лендінг: hero в один екран, WebGL-фон, сітка продуктів (заголовок окремо, картки в один ряд), бургер-меню ≤900px, акордеон з 8 статтями + 3 FAQ, scroll-spy, OG-мета;
- пройдено `$impeccable critique` (36/36 оцінених пунктів зелені), контраст AAA 7–17.7:1, нуль горизонтального overflow на 12 ширинах;
- деплой: редагування файлів у `/Volumes/Work/8fc8/...` = миттєве оновлення продакшну (bind-mount, без rebuild);
- git: робоче дерево чисте, останній коміт `900e0ed` (на момент оновлення SPEC).

**Що змінюємо:** нічого прямо зараз — змін у процесі немає. Наступні заплановані зміни: (1) перша мовна копія з канону + деплой на вільний 180xx порт; (2) HTTPS; (3) брендований og:image 1200×630.

**Що не змінюємо:** структуру `versions/en-US-landing/`; bind-mount деплой (не перетворювати на copied image); зайняті публічні порти 18080/18082/18083/18084/18085/18088/18090/18091; правило форвардингу `nexxgsm-landing` на зовнішньому Keenetic; admin→frontend даних немає — контент редагується прямо у файлах версії.

**Ризики:**
- **HTTP без TLS** — паролі/оплата через Telegram-бот, але сторінка передачі даних незашифрована; для продакшну з оплатою HTTPS бажаний найближчим часом.
- `og:image` відсутній — прев'ю в Telegram/X без банера (є мета-теги, банер чекає на актив).
- `testing/node_modules` на цьому зовнішньому томі пошкоджений (ломає великі JS-бандли при записі) — `npx backstop test` локально не запуститься, поки не перевстановити на здоровому томі; smoke-тести натомість через Playwright з `/tmp`.
- Публічний простір 180xx спільний з іншими застосунками ланцюжка роутерів — перед новим деплоєм перевіряти і NAS (`netstat`), і зовнішню доступність порту.
- Внутрішній Keenetic (192.168.2.1) не в ланцюжку публічних сайтів — його форвардинги (3000, 18085) ззовні не відкриваються; це норма, не поломка.

**План:**
1. Обрати культуру першої копії за `shared/keywords-research.md` → скопіювати канон → адаптувати текст/валюту/контакти → деплой контейнером на вільний 180xx порт → форвардинг RCI → перевірка.
2. HTTPS: reverse-proxy на NAS або Keenetic + Let's Encrypt (окреме рішення, зафіксувати в architecture-decisions).
3. og:image банер у візуальній мові «8FC8» + `twitter:card summary_large_image`.

**Перевірка:**
- після кожної зміни: `curl -w "%{http_code}" http://nlmhelp.keenetic.link:18080/` + spot-check контенту (bind-mount = продакшн бачить зміну одразу);
- UI: скріншот/geometry-перевірки на 320/390/768/1280 (+ проміжні 360/480/600/900/1100), нуль overflow, консоль чиста;
- регресії: `node testing/quick-test.js` (overflow-свуп; очікує сервер на :8080 з `versions/`);
- текстові файли: UTF-8 без BOM, скан на mojibake (Рџ/РЅ/�).
